# Commands

Generated by `scripts/gen-docs.py` from the commands themselves; `qbd help <command>` prints the same text.
Every command prints one line of JSON (add `--pretty` to indent it, `--out FILE` to write it to a file) and
takes `--demo` to run against the built-in sample company instead of QuickBooks.

```

and exits with 2 (change the command), 3 (a person must act at the PC) or 1 (anything else).

  qbd stock-history <item>    Why an item's stock is what it is

## Workflows

### qbd daily-brief

```
Usage: qbd daily-brief [options]

Daily finance brief.
Morning summary of the business: cash in the bank, money owed by customers and how late it is, bills
due soon, sales this month against the same days last month, yesterday's transactions and stock
below reorder point, with a list of what needs attention today.

  --upcoming-days N  How far ahead to list bills coming due; 1 to 60; default 7
```

### qbd trace

```
Usage: qbd trace <ref> [options]

Follow a document through its chain.
Start from one transaction, by its number or TxnID, and follow QuickBooks' links: estimate or sales
order to invoices, payments and the bank deposit; purchase order to item receipts, bills and bill
payments; and back. Each document has its state (open, paid, fully invoiced, waiting in Undeposited
Funds...), and loose_ends lists what is still to do. Use it for "where is this order?" or "was this
invoice paid and banked?".

  <ref>          The transaction's number (RefNumber), or its TxnID; required
  --type CHOICE  The record type, when several transactions have this number; one of: invoice,
                 estimate, sales_order, sales_receipt, credit_memo, receive_payment, deposit, charge,
                 bill, vendor_credit, bill_payment_check, bill_payment_credit_card, check,
                 credit_card_charge, credit_card_credit, purchase_order, item_receipt, journal_entry,
                 inventory_adjustment, build_assembly, transfer, transfer_inventory,
                 sales_tax_payment, time_tracking, transaction
```

### qbd receivables

```
Usage: qbd receivables [options]

Who owes money (collections list).
Who owes money, from QuickBooks' A/R aging: customers most overdue first, with contact details, days
late, a suggested reminder step and their open invoices. Payments and credits not applied yet are
used on the oldest invoices first and flagged, to apply before chasing. Use it to plan collections
calls and emails. totals.open is QuickBooks' A/R total: what customers owe less the credit_balances
of customers who paid more than they owe, so totals.overdue, which counts only customers who owe,
can be larger.

  --customer TEXT            Only this customer (full name)
  --top N                    How many customers to list; 1 to 100; default 15
  --invoices-per-customer N  0 to 50; default 5
  --open                     Also draw it as a page and open it in the web browser
```

### qbd match-payment

```
Usage: qbd match-payment <customer> <amount> [options]

Which invoices a payment pays.
For a payment from a customer, the open invoices it most likely pays, from QuickBooks' A/R aging:
the invoice numbers named in the remittance text, the one invoice with that open amount, the oldest
invoices in order, or another set of up to five that adds up exactly; otherwise oldest first, with
what stays open and the nearest invoice. Says how sure the match is, lists the alternatives, and
gives the fields for qbd draft add receive_payment.

  <customer>         The customer (its jobs included); required
  <amount>           The payment amount, e.g. 1250.00; required
  --memo TEXT        The remittance text or reference that came with the payment
  --date YYYY-MM-DD  The payment date (default: today)
```

### qbd deposits

```
Usage: qbd deposits [options]

Payments waiting to be deposited.
Customer payments and sales receipts waiting in Undeposited Funds, oldest first, by payment method
and by day. Give the amount of a deposit on the bank statement to find which of them make it up: one
payment, one day's payments of one method (card batches arrive that way, sometimes less the
processor's fee), everything waiting, or another set of up to five that adds up exactly. Gives the
fields for qbd draft add deposit.

  --amount TEXT      The deposit amount on the bank statement, e.g. 2875.67
  --date YYYY-MM-DD  The deposit date on the bank statement (default: today)
  --account TEXT     The bank account it went to, for the draft fields
  --limit N          Most payments listed; 1 to 1000; default 50
```

### qbd payables

```
Usage: qbd payables [options]

Bills to pay.
Bills to pay, from QuickBooks' A/P aging: what is overdue, what falls due in the next days, totals
per vendor and the cash needed. Vendor credits and payments not applied yet are used on each
vendor's oldest bills first and flagged, to apply when paying. Use it to plan a payment run.

  --vendor TEXT   Only this vendor
  --days-ahead N  1 to 90; default 14
  --top N         How many vendors to list; 1 to 100; default 20
```

### qbd coding

```
Usage: qbd coding <vendor> [options]

How a vendor's spending is coded.
How a vendor's bills, checks and credit card charges were coded: the accounts and items their lines
went to, with classes, how many transactions, totals, the typical amount, item costs, recent memos
and the latest one; the accounts QuickBooks pre-fills for the vendor; and transactions coded to a
holding account such as Uncategorized Expenses, or unlike all the others. Use it before drafting a
bill or expense, as the evidence for the account to choose, or to check a new bill's prices against
past costs.

  <vendor>           The vendor; required
  --from YYYY-MM-DD  Oldest transaction date to read (default: a year ago)
  --limit N          Most transactions of each kind to read; 1 to 5000; default 500
```

### qbd cash-position

```
Usage: qbd cash-position [options]

Cash position and short-term forecast.
Cash in the bank now and a week-by-week estimate for the coming weeks from invoice and bill due
dates, with the lowest point. An estimate: it does not know payroll, rent or other costs that are
not entered as bills.

  --days-ahead N              7 to 90; default 30
  --count-overdue-receivables Assume overdue invoices are paid in the first week
  --open                      Also draw it as a page and open it in the web browser
```

### qbd reorder

```
Usage: qbd reorder [options]

What to reorder.
Inventory items that need reordering, from reorder points, stock on order, open sales orders and
recent sales speed, grouped by preferred vendor with a suggested quantity and cost. Ready to turn
into purchase orders.

  --vendor TEXT      Only items whose preferred vendor is this
  --lookback-days N  Sales history used for sales speed; 14 to 365; default 90
  --cover-days N     Days of sales the stock should cover; 7 to 180; default 30
  --limit N          1 to 500; default 60
```

### qbd stock

```
Usage: qbd stock [options]

Stock by item and site.
On hand, on sales orders, available and on purchase orders for each inventory and assembly item, per
site when inventory sites are on (Advanced Inventory). Available is on hand minus open sales orders
and parts reserved for pending builds, as QuickBooks counts it. A row is oversold when available is
below zero, and at the reorder point when available plus what is on order is at or under it; such
rows show what the other sites have available.

  --items A,B  Exact item names (full names); every active inventory and assembly item when left out
  --site TEXT  Only this site
  --short      Only rows that are oversold or at the reorder point
  --limit N    Most rows; 1 to 2000; default 200
```

### qbd backorders

```
Usage: qbd backorders [options]

Which open orders can ship.
Open sales-order lines checked against stock the way QuickBooks Enterprise's Sales Order Fulfillment
Worksheet does: stock goes to the oldest orders first, at each line's site when inventory sites are
on. Lists the lines that can ship in full now, and the short lines with the purchase orders on the
way, when they should cover them, and the free stock at other sites. Use it to plan picking and
transfers, and to tell customers when the rest will come.

  --customer TEXT    Only this customer's orders
  --from YYYY-MM-DD  Oldest order date to read (default: a year ago)
  --limit N          Most lines in each list; 1 to 1000; default 50
```

### qbd purchasing

```
Usage: qbd purchasing [options]

Purchase orders to chase.
The buyer's worklist: purchase order lines past their expected date and still not received, the open
order value per vendor, goods received on an item receipt whose bill was never entered (received,
not billed), and a three-way match: bills against the order they were made from (cost and quantity),
and bills for items an open order waits for that were never linked to it. Use it to chase vendors,
before paying bills, or before month end.

  --vendor TEXT      Only this vendor
  --from YYYY-MM-DD  Oldest order date to read (default: a year ago)
  --limit N          Most lines listed in each part; 1 to 1000; default 50
```

### qbd stock-history

```
Usage: qbd stock-history <item> [options]

Why an item's stock is what it is.
One inventory or assembly item's movements from QuickBooks' Inventory Valuation Detail report, with
the quantity on hand after each, and every time the item went below zero: the transaction that took
it there, how low it went and what brought it back. A sale entered before the purchase that supplied
it is costed at the average cost of the day, and the purchase corrects cost of goods sold on its own
date, so each time matters, not only today's quantity. Use it when an item shows negative stock or
its cost of goods sold looks wrong.

  <item>             The item's full name; required
  --from YYYY-MM-DD  First date (default: a year before to)
  --to YYYY-MM-DD    Last date (default: today)
  --limit N          Most movements listed, the latest; 1 to 1000; default 50
```

### qbd 1099

```
Usage: qbd 1099 [options]

1099 worklist.
The vendors to send a 1099 for a calendar year: what each was paid by check or cash on the accounts
the company file maps to 1099 boxes, the way QuickBooks' 1099 wizard counts it (card payments are
left out: the card company reports them), who is over the IRS threshold for that year, whose tax ID
or address is missing, and vendors not marked for 1099 that were paid over the threshold on mapped
accounts. Tax IDs are never shown, only whether one is on file.

  --year N   Calendar year of the payments (default: last year until April, then this year so far);
             2000 to 2100
  --limit N  Most vendors in each list; 1 to 1000; default 100
```

### qbd uncleared

```
Usage: qbd uncleared [options]

Uncleared bank and card items.
Bank and credit card transactions still not cleared after some days (checks never cashed, deposits
the bank never saw, entries made twice), oldest first and with a likely twin when there is one, plus
items marked in a reconciliation that was left unfinished. Use it before reconciling, or when a
reconciliation does not match.

  --account TEXT       One bank or credit card account; every one when left out
  --older-than-days N  Not cleared for at least this many days; 0 to 3650; default 30
  --from YYYY-MM-DD    Oldest date to look at (default: a year ago)
  --limit N            Most items listed; 1 to 1000; default 100
```

### qbd reconcile-check

```
Usage: qbd reconcile-check <account> [options]

Why a reconciliation's beginning balance is off.
For a bank account whose beginning balance in Reconcile no longer matches the bank statement: adds
up what QuickBooks counts as reconciled (its beginning balance), compares it with the bank's balance
at the end of the last statement reconciled, and lists reconciled transactions changed or voided
since that reconciliation and bank transactions deleted since then, which is where such a difference
comes from. Nothing is changed.

  <account>                   The bank account; required
  --statement-date YYYY-MM-DD End date of the last statement reconciled; required
  --bank-balance TEXT         The bank's balance on that date, e.g. 12450.37 (the next statement's
                              beginning balance); required
  --reconciled-on YYYY-MM-DD  The day that reconciliation was done (default: statement_date)
  --limit N                   Most transactions listed; 1 to 500; default 50
```

### qbd price-check

```
Usage: qbd price-check [options]

Sales priced below the price list.
Invoice and sales receipt lines priced below what the item list and the customer's price level say,
with what the difference cost, by customer, item and sales rep, plus the discount lines given
openly. Catches discounts nobody approved and old prices typed by hand. Lines are compared with
today's prices, so an item whose price changed since the sale shows up too; Advanced Pricing's price
rules cannot be read through the SDK, so only price levels count.

  --from YYYY-MM-DD    First date (default: 90 days before to)
  --to YYYY-MM-DD      Last date (default: today)
  --customer TEXT      One customer (and its jobs)
  --min-gap-percent N  Ignore lines less than this many percent below the expected price; 0 to 100;
                       default 1
  --limit N            Most lines listed; 1 to 500; default 25
```

### qbd sales-tax-check

```
Usage: qbd sales-tax-check [options]

Why sales tax owed and the books disagree.
US sales tax: compares what QuickBooks' Sales Tax Liability report says is owed with the Sales Tax
Payable balance on the balance sheet (accrual and cash) on a date, and lists what usually splits
them: sales tax paid with Write Checks, a bill or a card charge instead of Pay Sales Tax, and
journal entries to Sales Tax Payable with no vendor. Nothing is changed.

  --as-of YYYY-MM-DD  The date to compare on (default today)
  --from YYYY-MM-DD   List transactions dated on or after (default a year before as_of)
  --limit N           Most transactions listed; 1 to 500; default 50
```

### qbd currency

```
Usage: qbd currency [options]

Foreign-currency balances explained.
Multicurrency files: QuickBooks' exchange rate for each foreign currency and the date it was set;
each foreign account's balance in its currency, what the books carry it at in the home currency,
what it is worth at the rate and the unrealized gain or loss, and the date of the last home currency
adjustment; customers, vendors and accounts with nothing left in their currency but a home-currency
balance still on them; and recent transactions whose exchange rate is far from the usual one, such
as 1 or a rate typed upside down. Nothing is changed.

  --rates A,B               Value at these rates instead of QuickBooks' own: CODE=RATE in home
                            currency per unit, e.g. USD=1.3712
  --days N                  Check the exchange rates of transactions from this many days back; 1 to
                            366; default 90
  --max-rate-gap-percent N  List a transaction whose rate is at least this many percent from the usual
                            one; 1 to 90; default 10
  --limit N                 Most names and transactions listed per currency; 1 to 200; default 20
```

### qbd find-duplicates

```
Usage: qbd find-duplicates [options]

Find duplicate entries.
Look for bills entered twice, bills also paid by a separate check or card charge, invoices billed
twice, repeated expenses, and customers or vendors that exist under two names. Each finding has a
confidence and the records involved. Nothing is changed.

  --from YYYY-MM-DD  Transactions dated on or after (default 90 days ago)
  --to YYYY-MM-DD    Transactions dated on or before (default today)
  --window-days N    Same amount within this many days counts as a possible duplicate; 0 to 31;
                     default 7
  --include A,B      comma-separated, from: bills, expenses, invoices, names; default
                     bills,expenses,invoices,names
```

### qbd health-check

```
Usage: qbd health-check [options]

Books health check (month-end readiness).
Checks the company file for what an accountant fixes before closing a month: closing date,
uncategorized amounts, Opening Balance Equity, undeposited payments, unapplied customer payments and
vendor credits, very old receivables and payables, negative stock, sales orders and purchase orders
left open, and future-dated transactions. Read-only.

  --period-end YYYY-MM-DD  Month end being closed (default: end of last month)
```

### qbd compare-periods

```
Usage: qbd compare-periods [options]

Compare profit and loss between periods.
Profit and loss for two periods side by side (default: last month against the month before), with
the lines that changed most. Use it to explain why profit moved.

  --current-from YYYY-MM-DD   Current period start
  --current-to YYYY-MM-DD     Current period end
  --previous-from YYYY-MM-DD  Previous period start
  --previous-to YYYY-MM-DD    Previous period end
  --basis CHOICE              one of: Accrual, Cash
  --top N                     1 to 50; default 12
```

```

### qbd changes

```
Usage: qbd changes <since> [options]

What changed since a time.
Transactions and list records (customers, vendors, items, accounts) added or changed since a date or
time, and records deleted since then, newest first. Transactions dated on or before the closing date
are flagged: someone changed a closed period. Pass next_since to the following call to pick up where
this one ended (records changed in that same second come back again). QuickBooks keeps deletions for
about 90 days, and a company file restored from a backup since then is reported.

  <since>    Date YYYY-MM-DD or date-time YYYY-MM-DDThh:mm:ss, in the QuickBooks computer's time;
             required
  --limit N  Most transactions, and most records per list; 1 to 1000; default 100
```

### qbd snapshot

```
Usage: qbd snapshot [options]

Balances and record counts, to compare later.
The company file's control totals: every account's balance and how many customers, vendors, items,
invoices, bills and other records it holds. Save one before a Rebuild, an upgrade, a condense or a
big import (qbd snapshot --out before.json), then compare after (qbd snapshot --compare
before.json): it lists the balances and counts that moved, so a person can see that only what should
change did. Read-only.

  --compare TEXT  A snapshot saved earlier with --out: show what moved since
```

### qbd raw

```

### qbd file-health

### qbd activity

```

### qbd addons

```
Usage: qbd addons [<action>] [<addon>] [options]

Add-ons: list, install, start or remove one.
Programs a person can add to qbd on this PC, such as the Activity Monitor: a window that shows what

## Changes (when QBD_ALLOW_WRITES=true)

### qbd draft

```
Usage: qbd draft <action> <type> [options]

Draft a change to QuickBooks.
Prepare an add, update, upsert, delete or void, and check it without saving anything: names must
exist, the date must be after the closing date, the amount under the limit, and it must not
duplicate an existing record. Returns a preview and a token. Show the preview to the person and run
qbd commit with the token only after they say yes. Field names are qbXML names (see qbd schema, e.g.
InvoiceAdd); references can be plain full names.

  <action>               upsert = update the list record with this name, or add it; one of: add,
                         update, upsert, delete, void; required
  <type>                 Record type, e.g. customer, vendor, invoice, bill, receive_payment,
                         purchase_order; one of: customer, vendor, employee, other_name,
                         item_inventory, item_assembly, item_non_inventory, item_service,
                         item_other_charge, item_group, item_discount, account, class, payment_method,
                         sales_rep, sales_tax_code, price_level, inventory_site, ship_method,
                         customer_type, vendor_type, currency, invoice, estimate, sales_order,
                         sales_receipt, credit_memo, receive_payment, deposit, charge, bill,
                         vendor_credit, bill_payment_check, bill_payment_credit_card, check,
                         credit_card_charge, credit_card_credit, purchase_order, item_receipt,
                         journal_entry, inventory_adjustment, build_assembly, transfer,
                         transfer_inventory, sales_tax_payment, time_tracking; required
  --fields JSON|@FILE|-  For add/update: the fields, e.g. {"CustomerRef": "Acme Ltd", "TxnDate":
                         "2026-10-20", "InvoiceLineAdd": [{"ItemRef": "Widget", "Quantity": 2, "Rate":
                         10}]}
  --id TEXT              ListID or TxnID of the record to update, delete or void
  --name TEXT            Lists: full name of the record to update, upsert or delete
  --reason TEXT          Why this change is made; kept in the audit log
  --source TEXT          Where the change comes from (a file name, an email's Message-ID, a CSV row);
                         a source already saved to this company file is refused, so the same document
                         is never entered twice
  --allow-duplicate      Draft it even though a matching record exists, or its source was already
                         saved
  --remove-lines A,B     Update: TxnLineIDs that the change removes on purpose
```

### qbd import

```
Usage: qbd import <type> [options]

Import records from a CSV file.
Check every record in a CSV file and draft them as one batch: invoices, bills, checks, journal
entries, customers, vendors, items and the other types qbd draft can add. Columns are qbXML field
names, as qbd export writes them: Customer (or CustomerRef), TxnDate, RefNumber,
BillAddress.City..., and Line.Item, Line.Quantity, Line.Rate, Line.Account, Line.Amount... for line
items (a LineKind column picks the kind of line; journal entries take Line.Account with Line.Debit
or Line.Credit). Rows with the same RefNumber are one transaction. Each record is checked like qbd
draft; records saved from this file before are skipped, so the file can be imported again after
fixing the rows that failed. Returns one token for the batch: show the preview and commit it only
after the person approves.

  <type>         Record type, e.g. invoice, bill, journal_entry, customer; one of: customer, vendor,
                 employee, other_name, item_inventory, item_assembly, item_non_inventory,
                 item_service, item_other_charge, item_group, item_discount, account, class,
                 payment_method, sales_rep, sales_tax_code, price_level, inventory_site, ship_method,
                 customer_type, vendor_type, currency, invoice, estimate, sales_order, sales_receipt,
                 credit_memo, receive_payment, deposit, charge, bill, vendor_credit,
                 bill_payment_check, bill_payment_credit_card, check, credit_card_charge,
                 credit_card_credit, purchase_order, item_receipt, journal_entry,
                 inventory_adjustment, build_assembly, transfer, transfer_inventory,
                 sales_tax_payment, time_tracking; required
  --csv TEXT     The .csv file to read (UTF-8; dates like 2026-10-31); required
  --reason TEXT  Why these records are entered; kept in the audit log with each one
  --limit N      Most records in one batch; import again for the rest; 1 to 1000; default 200
```

### qbd commit

```
Usage: qbd commit <token> [options]

Save an approved draft to QuickBooks.
Send a change prepared by qbd draft, or a batch prepared by qbd import, to QuickBooks. Only run this
after the person has seen the preview and said yes. Each token works once and expires after 15
minutes. When the person answered the draft in the Activity Monitor, this returns what they decided:
what was saved, or that they rejected it.

  <token>               The token from qbd draft or qbd import; required
  --approved-in CHOICE  Where the person approved it; the Activity Monitor sets monitor when they
                        approve it there; one of: chat, monitor; default chat
  --seen TEXT           The draft's fingerprint as the person saw it. The Activity Monitor sends it,
                        so that a draft changed after it was shown is not saved
```

### qbd undo

```
Usage: qbd undo <token>

Draft the undo of a saved change.
Find a change saved through qbd commit in the write log by its token and draft its reverse: an added
record is deleted (needs QBD_ALLOW_DELETE), an update puts the old values back. Deletes, voids,
changes to lines or to card and ID data, and records changed again since are refused; the log keeps
their old values for a person to redo. Returns a draft like qbd draft: commit it only after the
person approves.

  <token>  The token of the saved change (qbd log lists them); required
```

  --limit N  1 to 200; default 20
```
